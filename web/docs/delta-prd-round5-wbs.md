## 一、产品目标（一句话）

**让 WBS 面板的三个高频动作（写日志、建下级、填进度）在交互上与 R4 已落地的"叶子加权聚合 + 引擎单点收口"数据模型保持语义一致——填完即收、父级不可篡改、进度只在叶子录入。**

## 二、需求明细

### R5-P0-1 · 写日志提交后关闭弹窗（停留 WBS，不跳转）

#### 产品描述

R4 将 WBS 行内「写日志」改为页内弹窗（`WbsPage.tsx:677-687`，`keepOpenOnSubmit` 传 `true`），当时把用户"不要跳转到工作日志看板"的诉求实现成了"弹窗常驻不关"。用户本次澄清：诉求是**不跳页面**，不是**不关弹窗**。

**代码现状（已核对）**：`ReportFormModal.doSave()`（第 200-216 行）在 `keepOpenOnSubmit=true` 时执行"保留打开 + reset 表单 + 保留 lockNodeId 勾选"分支；为 `false` 时调用 `onClose()`。ReportsPage 已传 `false`（第 183 行）。WBS 入口本身不含任何 `navigate`，**不跳转这一点当前已经满足**，本需求只需切换关闭行为。

#### 用户故事

> 作为项目经理，我在 WBS 树里点某个叶子任务的「写日志」填完并提交后，希望弹窗自动关闭、页面仍停留在 WBS 树上并看到该行进度条已刷新，这样我能立刻确认这次填报的效果，而不是对着一个空表单猜"到底存进去没有"。

#### 验收标准（P0）

| # | 验收项 | 期望 |
|---|---|---|
| AC-1.1 | WBS 行「写日志」→ 填写 → 点「提交」 | 成功 toast「工作日志已提交」后**弹窗关闭** |
| AC-1.2 | 同上，点「存草稿」 | 成功 toast「工作日志已存草稿」后**弹窗关闭**（与 ReportsPage 入口行为一致） |
| AC-1.3 | 关闭后页面位置 | 仍在 `/projects/:id/wbs`，**不发生任何路由跳转**，滚动位置不重置 |
| AC-1.4 | 关闭后数据刷新 | 现有 `onSubmitted` 回调（`fetchWbs` + `refreshMilestones`）仍执行，关闭后 WBS 行进度条/状态 Chip/「日志 N」徽标均为最新值 |
| AC-1.5 | 提交失败（引擎抛错） | 弹窗**不关闭**，表单内容保留，仅 toast 报错（现有 catch 分支行为不变） |
| AC-1.6 | 锁定态无残留 | 关闭后从**另一个**节点再次点「写日志」，弹窗内锁定勾选的必须是新节点，不得残留上一个节点 |
| AC-1.7 | 连续填报路径不丢失 | 用户仍可通过"再点一次另一行的写日志"完成连续填报（每次弹窗预关联对应节点） |

### R5-P0-2 · 创建下级任务时上级节点锁定不可改

#### 产品描述

**代码现状（已核对）**：`WbsPage.openCreate(parentId)`（第 195-208 行）已把父节点 id 预填进 `form.parentId`，并已继承父节点的 `milestoneId` / `dueDate`；但弹窗内「上级节点」是一个**完全可改的 Select**（第 474-490 行，`onChange → changeParent`）。用户从节点行「+」进入本意是"在这个节点下建下级"，一旦改了上级，语义就变成了"挑个别的地方建"，与入口预期不符，也容易误触。

同一弹窗内已存在成熟的锁定范式：「关联里程碑」的 `lockMilestone`（第 526-537 行，`disabled` + label 追加「已继承上级·锁定」+ helperText 解释）。本需求复用同一表现范式。

> 注：具体实现走 `lockMilestone` 式的本地 lock state、还是复用 R4 `lockNodeId` 的思路，由工程决定，PRD 不指定。

#### 用户故事

> 作为项目经理，我在 WBS 树里点某个任务右侧的「+」创建下级任务时，希望上级节点已经填好且不能改，这样我不会在填了一半后手滑把新任务挂到别处；如果我真的要挪节点，我会去编辑那个节点改上级。

#### 适用范围（关键边界）

| 入口 | 上级节点字段 | 说明 |
|---|---|---|
| 节点行「+」（创建下级） | **锁定**（disabled） | 本次变更点 |
| 卡片右上「新建任务」（`openCreate('')`） | **保持可选** | 从根层发起，用户需要自行决定挂哪里 |
| 节点行「编辑」（`openEdit`） | **保持可改** | 这就是合法的"移动节点"路径，不受本次变更影响 |

#### 验收标准（P0）

| # | 验收项 | 期望 |
|---|---|---|
| AC-2.1 | 从节点「+」进入 | 「上级节点」显示该节点 `wbsCode + 名称（类型）`，控件 **disabled**、不可展开下拉 |
| AC-2.2 | 锁定态提示 | 字段带锁定语义标识（label 后缀或锁图标）+ helperText 说明「由「创建下级任务」进入，上级已锁定；如需调整层级请到该节点「编辑」中修改上级」 |
| AC-2.3 | 提交结果 | 创建出的节点 `parentId` 严格等于入口节点 id |
| AC-2.4 | 与里程碑继承共存 | 原有「关联里程碑」继承+锁定（`lockMilestone`）行为不变，两个锁定可同时出现且文案不冲突 |
| AC-2.5 | 类型下拉不受影响 | 「节点类型」仍按 `allowedChildTypes(formParent, rules)` 动态过滤；上级锁定后可选类型集合恒定，不再因换父而收敛 |
| AC-2.6 | 校验链路不变 | `validateWbsPlacement` 前端预校验与引擎兜底逻辑保持原样 |
| AC-2.7 | 顶部「新建任务」回归 | 从 SectionCard 右上「新建任务」进入时，上级节点仍可自由选择（含"（根节点）"） |
| AC-2.8 | 编辑态回归 | 编辑已有节点时上级节点仍可改，改后仍触发 `changeParent` 的继承逻辑 |

### R5-P0-3 · 有子节点的任务不可直接关联日志/填进度

#### 产品描述

**问题的真实根因（已在代码中核对确认）**：

1. `ReportFormModal.renderTaskTree()`（第 223-266 行）对**全部**节点（含父节点）渲染 checkbox 与「完%」输入框；
2. `assemble()`（第 177-181 行）把**全部**节点打进 `payload.tasks`，父节点也带 `progressAfter`；
3. `upsertReport()`（`mock/index.ts:1606-1614`）遍历 **全部** `report.tasks`（不区分 `selected`）执行 `node.progress = t.progressAfter`，父节点存储进度被直接改写；
4. 紧接着 `syncWbsProgressStatus()`（第 318-332 行）用 `rollupProgressFlat` 把每个父节点 progress **重算覆盖**为"子树真叶子按 estimateDays 加权"。

**结果**：用户给父任务填的进度会被引擎静默丢弃，但这条数字仍被冻结进 `report.snapshot` 和 `report.tasks[].progressAfter`，导致「日志详情里写着 60% → WBS 上显示 35%」的账实不符。**这是一个当前可复现的数据一致性问题，不只是体验问题。**

因此：父节点进度必须**纯由子任务加权聚合**，UI 层不应提供任何直接录入入口。

#### 用户故事

> 作为填报人，当我要给一个已经拆出子任务的父任务写进度时，系统应该直接告诉我"去子任务里记"，而不是让我填一个提交后会被悄悄改掉的数字。
>
> 作为项目经理，我看 WBS 父节点进度时，希望它百分百等于子任务的加权汇总，不会被谁在日志里手填一个数搅乱。

#### 变更点（两层拦截）

**① 源头拦截 — WBS 行「写日志」入口只出现在叶子节点**

`WbsPage.renderNode()` 内 `isLeaf`（第 304 行）已是现成判定，「写日志」按钮（第 358-372 行）当前对全部节点渲染。

**② 兜底拦截 — 共享弹窗内父节点行不可勾选、不可填进度**

因为 ReportsPage「新建日志」入口没有节点上下文，用户仍会在弹窗任务树里直接勾。规则必须落在 `ReportFormModal` 内，两个入口自动一致。

#### 验收标准（P0）

| # | 验收项 | 期望 |
|---|---|---|
| AC-3.1 | WBS 叶子节点行 | 「写日志」按钮正常显示可点（权限与归档规则不变） |
| AC-3.2 | WBS 父节点行 | **不提供可用的「写日志」入口**（禁用置灰或 Tooltip 引导） |
| AC-3.3 | 弹窗任务树 · 父节点行 | checkbox **禁用且不可勾选**，「完%」输入框**禁用**，行内给出"父任务进度由子任务汇总"的说明 |
| AC-3.4 | 弹窗任务树 · 叶子行 | 行为完全不变（可勾选、可填进度） |
| AC-3.5 | 提交数据洁净性 | 提交后，本次日志中**任何父节点**的 `selected` 必须为 `false`，且其 `progressAfter` 必须等于该节点提交前的存储进度（不得携带用户输入值） |
| AC-3.6 | 账实一致 | 提交后，日志详情弹窗中任一任务的 `progressAfter` 与 WBS 树上该节点当前进度**完全一致**，不再出现前述 60%/35% 偏差 |
| AC-3.7 | 父节点进度口径 | 父节点进度仍严格等于 `rollupProgress`（视图）/ `rollupProgressFlat`（存储），本需求不改动任何聚合算法 |
| AC-3.8 | lockNodeId 防御 | 若 `lockNodeId` 指向的节点已有子节点（如 ReportsPage 旧链接 `prefillNodeId` 兼容路径），**不得锁定该节点**，降级为普通新建并提示「该任务已有下级，请到具体子任务记录进度」 |
| AC-3.9 | 编辑态回归 | 编辑已提交日志时任务树仍整体只读，历史上已关联父节点的存量日志**照常展示**，不报错、不被清洗 |
| AC-3.10 | 徽标口径不变 | WBS 行「日志 N」徽标仍按 `selected=true` 计数；父节点因不能再被勾选，新日志不会再增加其计数（历史计数保留） |
| AC-3.11 | 极端场景 | 若整棵树的根任务全部有子节点，用户仍可通过叶子行入口或工作日志页「新建日志」正常填报，不出现"无处可填" |

## 三、UI 交互细节

### 3.1 弹窗关闭行为（R5-P0-1）

| 场景 | 弹窗 | 页面 | Toast |
|---|---|---|---|
| WBS 入口 · 提交成功 | 关闭 | 停留 WBS，树数据刷新 | 「工作日志已提交」 |
| WBS 入口 · 存草稿成功 | 关闭 | 停留 WBS | 「工作日志已存草稿」 |
| WBS 入口 · 失败 | 保持打开、内容保留 | 停留 WBS | 错误信息 |
| ReportsPage 入口 | 关闭（现状不变） | 停留列表 | 不变 |
| 手动点右上角关闭/取消 | 关闭（不变） | — | 无 |

### 3.2 上级节点锁定表现（R5-P0-2）

- **控件形态**：仍为原「上级节点」Select，`disabled` 状态，值为只读展示 `1.2 接口联调（任务）`
- **锁定标识**：label 追加「（已锁定）」或前置锁图标 —— 与 R4 写日志锁定的锁图标 + Tooltip 范式保持一致
- **helperText**：`由「创建下级任务」进入，上级节点已锁定；如需调整层级，请到该节点「编辑」中修改上级`
- **不改动**：类型下拉、名称、里程碑、截止日期、负责人、工时、状态各字段的既有行为与 helperText
- **视觉一致性**：与同一弹窗中已有的「关联里程碑（已继承上级·锁定）」共用同一套禁用样式与文案语气

### 3.3 关联任务下拉/树的禁用规则（R5-P0-3）

**采用"禁用可见"而非"隐藏"**（理由：任务树是层级结构，隐藏父节点会让子节点失去缩进上下文，用户找不到自己的任务；且父行的汇总进度条本身是有价值的参考信息）。

| 行类型 | checkbox | 「完%」输入 | 进度条 | 文案 |
|---|---|---|---|---|
| 叶子节点 | 可勾选 | 可编辑 | 显示自身进度 | 无 |
| 父节点（有子节点） | **禁用**、视觉弱化 | **禁用**、灰显当前汇总值 | 显示汇总进度（保留 Tooltip） | 行内 caption 或 Tooltip：`该任务已有下级，进度由子任务加权汇总，请在子任务中记录` |
| 父节点 + 编辑态 | 禁用（现状即禁用） | 禁用（现状即禁用） | 显示 | 沿用「编辑已提交日志时该区域只读」 |
| 锁定节点（叶子） | 勾选+禁用+锁图标 | 可编辑（R4 规则不变） | 显示 | 「由「写日志」进入，该任务已锁定；可继续勾选其他任务」 |

区域标题右侧提示语增补一句统一说明：`父任务进度由子任务汇总，不可直接勾选`。

### 3.4 父节点「写日志」入口可见性（R5-P0-3）

采用 **保留按钮 + 禁用 + Tooltip 引导**（对齐同行「新建子节点」按钮"不可用时 disabled + Tooltip 解释"的既有范式），理由是行布局不跳动、且能教育用户为什么不能填：

| 节点 | 「写日志」按钮 | Tooltip |
|---|---|---|
| 叶子 + 有权限 + 未归档 | 可点 | 无 |
| **父节点**（有子节点） | **禁用置灰** | `该任务已有下级，请在具体子任务上记录工作日志` |
| 项目已归档 | 禁用（现状） | 「项目已归档」 |
| 无 `report:write` 权限 | 不渲染（现状） | — |

|---|---|---|

| `lockNodeId` 锁定范式（checked+disabled+锁图标+Tooltip） | 第 227-242、320-324 行 | R5-P0-2 的上级节点锁定沿用同一视觉与文案语气 |
| `lockMilestone` 字段级锁定范式 | `WbsPage.tsx` 第 526-537 行 | R5-P0-2 的字段级表现直接对齐（disabled + label 后缀 + helperText） |
| `isLeaf` / `node.children.length === 0` | `WbsPage.renderNode` 第 304 行 | R5-P0-3 的入口可见性判定直接复用，无需新增判定函数 |
| `rollupProgress` / `rollupProgressFlat` | `utils/wbs.ts` | **不改**。本轮是让 UI 与该口径对齐，而非改口径 |
| `syncNodeStatusFromProgress` | `rules.ts:596-600` | **不改**。父节点状态仍由聚合进度推导 |
| `syncWbsProgressStatus` 六写路径单点收口 | `mock/index.ts:318-332` | **不改**。本轮不新增写路径 |

| 「日志 N」徽标 `selected=true` 口径 | `utils/reportAgg.ts` | 口径不变 |

### 4.2 本轮新增的约束（均为 UI 层）

| 编号 | 新增约束 | 性质 |
|---|---|---|
| C-1 | WBS 写日志入口提交/存草稿后一律关闭弹窗 | 交互行为变更 |
| C-2 | "创建下级"语境下上级节点为只读；"移动节点"唯一合法路径收敛到「编辑」 | 语义边界约束 |
| C-3 | 非叶子节点不得成为新日志的关联对象，也不得在日志中被录入进度 | **数据一致性约束**（修复现存账实不符） |
| C-4 | `lockNodeId` 必须校验目标为叶子，非叶子时降级 | 防御性约束（保护旧链接兼容路径） |

### 4.3 明确不在本轮范围

- 不改任何聚合算法、状态流转规则、引擎写路径
- 不清洗历史日志中已关联父节点的存量数据（只读展示保持原样）
- 不改 ReportsPage 列表、详情弹窗、编辑态只读规则
- 不动 `prefillNodeId` 旧链接兼容能力本身（仅加叶子校验）
- 不涉及权限模型（`report:write` / `wbs:edit` 判定不变）
