## 1. 产品目标

1. **建项体验回归极简**：新建项目向导不再出现「必备 / 有质量门」等已下线概念，用户可见文案归零，消除反复质疑（反馈①）。
2. **WBS 进度可视化可信**：父节点汇总进度条保留并按子任务统计；进度达 100% 自动流转任务状态，里程碑完成度实时反映任务进展（反馈④⑤）。
3. **日志录入零跳转**：从 WBS 写日志不再跳到工作日志看板，预关联任务锁定不可取消，支持连续添加（反馈③）；里程碑状态来源透明，用户秒懂「为什么进行中」（反馈②）。

## 2. 用户故事（5 条，对应 5 项反馈）

1. **作为 PM**，我在新建项目的里程碑规划步骤里**不应再看到「必备 / 有质量门」**，因为这些概念已确认下线，避免我反复困惑「怎么还没去掉」。

4. **作为 PM**，我创建下级任务后，**原有任务的进度条不应消失**，而应保留并按子任务进度汇总；任何任务/子任务进度到 100% 时**自动改状态**，上级任务与里程碑联动反映。
5. **作为任何用户**，进度条**悬停时能看到百分比**，不同状态（未开始/进行中/已完成等）的进度条**颜色可区分**，节点行有**状态标识**。

## 4. 五项决策结论（A~E）

### A. 残留清理（反馈①）—— 明确清理，范围 = 建项流程

**核实结论**：向导里程碑规划步骤残留**唯一可见项** = `ProjectCreatePage.tsx` L728-730「有质量门」Chip（`m.gate &&` 条件渲染，直接命中反馈①）；分类步骤 L530 副标题「最终分类（决定生命周期模板与质量门）」为第二处可见残留；**「必备」已无 UI 残留**（全库 tsx 仅注释/类型/引擎字段命中）。其余命中（`AdminTemplatesPage` 质量门数列、`MilestonesPage` 注释、`types/api.ts` 错误码等）属后台预览或内部语义，不在建项流程内。

**决策**：
- 清理范围：向导里程碑规划步骤 Chip（删除整块条件渲染）+ 分类副标题改写 + 确认页/提示文案排查（本轮 Read 未发现其他可见残留，验收以 grep 归零为准）。
- **引擎 `required` / `gate` 字段保留**（模板血缘，K-1 仅下线「新建项目生成质量门」流程，字段仍需写入引擎），**只清 UI/文案**。
- AdminTemplatesPage 是否一并清理 → **列入待确认**（P2-1），默认建议保留为后台模板元数据预览。

### B. M1/M2 进行中语义（反馈②）—— 选「方案2 来源标识 + 方案1 tooltip 组合」

**核实结论**：`deriveMilestoneStatus` P4：`progress > 0 || diffDays(startFrom, today) >= 0 → 进行中`。首碑 `startFrom = planStart`（建项当天=今天）→ 立即「进行中」；M2 的 `startFrom = M1.currentDate`（首碑若同日则 M2 同日）→ M1/M2 同时「进行中」。这是**时间轴语义的正确表现**（起算日已过即开工），不是 bug。

**决策**：**不做方案3**（首碑建项当天不显示进行中会破坏时间轴语义）。采用 **方案2（来源标识）为主 + 方案1（tooltip）为辅**：
- 状态列「进行中」旁灰字来源标签：时间驱动（progress=0 且 startFrom≤today）／任务驱动（progress>0）。
- tooltip 话术（用户秒懂）：「已到计划起算日 2025-xx-xx，按时间轴自动进入进行中；如需调整可人工覆盖状态」。
- 落地：状态派生时引擎/展示层可带出 `drivenBy: 'time' | 'task'` 标注（纯展示，不改判定）。

### C. WBS 写日志交互形态（反馈③）—— 选「方案1：WBS 页内 Modal」

**核实结论**：现状 = 跳转 ReportsPage + `state.prefillNodeId` 自动开弹窗；新建态预关联节点 checkbox **可取消**（仅编辑态 disabled）；提交后 `doSave` 关闭弹窗、停留在看板页。

**决策**：**方案1（体验最好、连续添加自然）**：
- 将 ReportsPage 的新建/编辑表单抽成共享组件 `ReportFormModal`，WBS「写日志」改为页内打开（不再跳转）。
- **锁定任务交互**：Modal 任务树中 prefill 节点 checkbox `checked + disabled`，右侧锁图标 + tooltip「由「写日志」进入，该任务已锁定；可继续勾选其他任务」；进度值输入框保持可编辑。
- **提交后行为**：WBS 入口提交成功 → Modal 保持打开、表单重置（周次默认本周、锁定任务不变）→ 支持连续添加；提供「关闭」返回 WBS 树。ReportsPage 原「新建日志」入口保持提交后关闭。

### D. 父节点进度汇总 + 100% 自动流转（反馈④，本轮核心）

#### D1 父节点进度条「消失」根因与验收
- **根因（已核实）**：`WbsPage.renderNode` L300 已算 `rollupProgress(node)`，但 L369-373 进度条被 `{isLeaf && ...}` 包裹 → **只在叶子渲染**。父节点一旦有子节点，`isLeaf=false`，进度条消失。汇总逻辑本身正确（wbs.ts `rollupProgress` 子叶子按 estimateDays 加权）。
- **修复**：移除 `isLeaf` 条件，所有节点渲染进度条；父节点值 = `rollupProgress`（已有），叶子值 = 自身 progress。注意父节点行无 estimateDays 展示（L374-378 也是 isLeaf 条件），需固定进度条宽度（120px）保证行对齐。
- **验收**：创建子任务后父节点进度条保留并按子任务统计；全叶子 100% → 父节点 100%。

#### D2 状态自动流转规则（人工覆盖边界明确）
- 任务状态集 = 现有 `TASK_STATUSES`（待办/进行中/待评审/完成/阻塞）；看板列 = 待办/进行中/待评审/完成。
- **自动流转规则**（引擎统一纯函数 `syncNodeStatusFromProgress`，触发点：createWbsNode / updateWbsNode / 日志提交 upsertReport / moveTask）：
  1. **强规则**：`progress >= 100 → status='完成'`（无条件，含当前为 阻塞/待评审 —— 满足用户「达到 100% 自动改状态」的硬性要求）。
  2. **弱规则**：`progress === 0` 且当前 ∈ {进行中, 完成} → 回落「待办」（防「没进度却进行中/完成」的脏状态）。
  3. **弱规则**：`0 < progress < 100` 且当前 ∈ {待办, 完成} → 置「进行中」。
  4. **人工覆盖边界**：当前状态为 **待评审 / 阻塞（人工态）时，除强规则 100% 外不被自动覆盖** —— 避免看板 WIP/评审语义被进度自动冲掉；用户手动改 progress 到 100 仍触发强规则。
  5. **父节点**：progress 回写 = 子树叶子加权汇总值（落库），status 按 1-3 同规则推导（全叶子 100%→完成；存在进行中叶子→进行中；全 0→待办）。
- **验收**：任一入口变更进度后，叶子与父节点 status 按上述规则收敛；待评审/阻塞仅被 100% 强规则覆盖。

#### D3 里程碑联动（谨慎规则，避免与 P4 时间驱动冲突）
- **决策**：**任务 100% 完成不自动达成里程碑**。理由：① 达成真值 `doneAt/doneBy` 需可审计归属，系统代写 doneBy 破坏审计语义；② 任务完成 ≠ 里程碑达成（可能仍有验收/门控/交付物）；③ 若自动达成，当前日期在未来时时间轴会「提前达成」，破坏 P4 时间驱动语义。
- **联动方式（两段式）**：
  - 里程碑 **完成度联动**（自动）：`taskStats.progress` 随叶子进度实时变化（已实现，口径 Y 仅真叶子加权）；**本轮修复联动缺口** —— 日志提交 `upsertReport` 回写进度后补调 `refreshMilestoneStatuses`，保证里程碑页/概览页数据实时一致。
  - 里程碑 **状态达成**（半自动）：关联叶子全部 100%（`progress===100 && total>0`）时，里程碑页显示「关联任务已全部完成」提示 + 「一键标记达成」入口（走既有 `updateMilestone{achieved:true}`，doneBy=当前用户、审计留痕）→ 与 P4 时间驱动并存、互不冲突。
- **验收**：任务全完成后里程碑状态仍由时间轴判定（进行中/未开始/已逾期），但 UI 出现完成提示与一键达成入口；用户确认后写入 doneAt/doneBy 并转「已达成」。

### E. 进度条 UX（反馈⑤）—— 复用现有 token/组件，零新增范式

- **Tooltip**：`ProgressBar` 外层包 MUI `Tooltip`，文案「{节点名} {progress}%（{状态}）」；WBS 树与 ReportsPage 任务关联树统一生效（叶子 + 父节点）。
- **状态色板**（复用 `tokens.status` 语义色，ProgressBar 已支持 `tone` 参数）：

  | 状态 | 语义 tone | 色值（浅色主题） | 说明 |
  |---|---|---|---|
  | 待办 / 未开始 | `neutral` | #546174 灰 | 未开工 |
  | 进行中 | `brand` | #2E7D87 青 | 品牌交互色，表示推进中（与 StatusChip 的 warning 映射解耦，进度条用青更直觉；如需全局一致可切 warning，见待确认⑤） |
  | 待评审 | `warning` | #B45309 琥珀 | 待检/评审 |
  | 完成 | `success` | #047857 绿 | 已达 100% |
  | 阻塞 | `danger` | #DC2626 红 | 风险阻断 |

  对比度说明：进度条为色块（非承载白字控件），语义色在浅色底辨识度足够；精确读数由悬停 Tooltip 承担（不依赖色觉）。
- **状态标识**：WBS 节点行在名称与里程碑 Chip 之间加 `StatusChip`（dot 或 soft variant，宽约 52px），所有节点可见（父/叶同规则）。`StatusChip` 已支持 `colorOf/toneOf` 自动取色，直接复用。
- **验收**：悬停任意进度条显示百分比；五种状态颜色可区分；节点行始终有状态标识。
