# E1.5 方案文档：职位（角色）可管理 + 多职位叠加

> 版本：v1（待用户签字）  
> 日期：2026-08-22  
> 目标：让"职位"成为可管理的配置项，支持一个人挂多个职位（全局型 + 项目型混合），权限按职位集合自动合并。

---

## 一、我们要解决什么（用大白话）

### 现状的痛点

1. **职位写死在代码里**：系统里有哪些职位、谁能看全局，都是程序员写定的，您没法自己在后台增删改。
2. **一个人的"全局职位"只能有一个**：比如某人既是公司 PMO（看全局）又是某项目的项目经理（看本项目），现在塞不进去第二个。
3. **项目内职位其实已经支持多个**（代码层面一人一项目可挂多条职位记录），但后台编辑界面没放开多选，所以您用不上。

### 我们要做成什么样

- **职位可管理**：后台能建/改/删职位，每个职位标"全局型 / 项目型"。
  - 全局型职位（如管理员、PMO、总技术负责人、管理层）：能看到并管理公司所有项目。
  - 项目型职位（如项目经理、技术负责人、开发、QA）：只在被指派的项目内有效，看不到别的项目。
- **一个人可挂多个职位**：全局职位和项目职位可以叠加，权限自动合并（并集）。
- **项目内可身兼多职**：同一人在一个项目里可以同时是"项目经理 + 技术负责人"，两个职位都生效。

### 不做的范围（明确划界，避免翻车）

- **业务线隔离先不做**（您已确认先放）。职位管理只管"全局型 / 项目型"这一层视野，不按业务线切数据。
- **审批流逻辑不动**：系统现在已是"A 项目的职位只能批 A 项目、公司层职位可跨项目批"，天然满足您的要求，无需改。
- **权限映射不开放界面勾选**：某个职位具体能干哪些操作，仍由系统按职位名称自动对应（沿用现有规则），不在界面上让人逐个勾。职位管理只管"有哪些职位、属于哪层、叫什么"。

---

## 二、业务逻辑（核心规则）

### 规则 1：职位带"视野类型"

每个职位定义时选一种：

- **全局型（global）**：持证人在公司范围内有效，可看全量。
- **项目型（project）**：持证人只在被指派进的具体项目里有效。

### 规则 2：一个人的有效职位 = 全局职位 ∪ 其各项目内的职位

- 登录后，系统拼出这个人的"职位集合"：
  - 他拥有的全部全局型职位（跨项目生效）；
  - 加上他在当前这个项目里被指派的全部项目型职位。
- 权限判定就用这个集合，任一职位命中即放行，多个职位取**并集**。

### 规则 3：项目型职位的"隔离"天然成立

- 某人在 A 项目是"技术负责人"、在 B 项目是"项目经理"，这两个职位各自锁在自己项目里。
- 因此 A 项目的审批/编辑，只有 A 项目的职位能参与；B 项目的同等职位进不来——这就是您要的"按项目隔离"，靠规则 2 自动实现，不用额外写逻辑。

### 规则 4：职位管理的增删改

- 后台"职位管理"页可：
  - **新建**职位（填名称 + 选全局型/项目型 + 描述）；
  - **编辑**职位（改名、改类型、启用/停用）；
  - **删除**职位（仅当没有任何人/项目正在使用它时允许）。
- 职位名称沿用现有那套（管理员、PMO、管理层、项目经理、技术负责人、开发、QA、产品经理等），不另造新词。

---

## 三、后台要新增/改造的页面（只说做什么）

| 页面             | 动作         | 说明                             |
| -------------- | ---------- | ------------------------------ |
| **职位管理（新建）**   | 新增一个后台页    | 列出所有职位，支持建/改/删 + 标全局型/项目型 + 启停 |
| **用户编辑（改造）**   | 全局职位改为可多选  | 一个人可勾选多个全局型职位                  |
| **项目成员管理（改造）** | 项目内职位改为可多选 | 同一人在本项目可勾选多个项目型职位              |

---

## 四、数据层面要动的（仅给负责人参考，不展开）

1. 新增"职位目录"：集中存放职位名称、类型（全局/项目）、启用状态。现有系统写死的职位名，迁入这张目录，并预置一套默认职位。
2. 全局职位从"每人只能一个"改为"每人可多个"（保留主职位用于兜底，不影响现有逻辑）。
3. 项目内职位：现有结构已支持多职位，本次主要是放开后台多选界面 + 确保权限按集合合并。
4. 权限判定内核：改为接收"职位集合"而非单个全局职位，按规则 2 合并判定。

---

## 五、验证标准（做完怎么算过关）

1. 后台能新建一个"全局型"职位和一个"项目型"职位，列表可见。
2. 给某用户同时分配"PMO（全局型）+ 某项目项目经理（项目型）"，该用户登录后：
   - 能看到公司全量项目（PMO 生效）；
   - 在该项目内有项目经理的全部操作权限（项目型生效）。
3. 同一人在一个项目里同时是"项目经理 + 技术负责人"，两个职位的权限都生效（并集）。
4. A 项目的"技术负责人"无法审批/编辑 B 项目（隔离成立，同现状）。
5. 停用某职位后，持该职位的人对应权限立即失效；删除职位仅在没有人使用时允许。
