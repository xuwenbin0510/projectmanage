# PRD · 项目类型后台可配置

> 版本：v1（简版）　日期：2026-09-11
> 来源：`docs/项目分类重构-草案.md`（设计已定稿，5 条决策已与业务方确认）
> 范围：仅产品口径，不含实现细节与存量数据迁移

---

## 1. 背景与目标

当前「项目类型」是写死在代码里的常量（前后端各一份 `PROJECT_TYPES = ['A','B','C','D']`），每新增一类项目都要改代码、发版。本需求把项目类型升级为**后台可维护的实体**：管理员可在后台**新增 / 编辑 / 停用**类型，并为每个类型挂接它自己的**生命周期模板（里程碑 + 质量门）** 与**审批流**；建项时从"启用中的类型列表"里**直接单选**。目标：以后新增类型（如"预研类"）只需后台配置，**零代码改动**。

**现状锚点**（落笔一致性）：
- 项目类型：写死（`server/config/enums.js`、`web/src/config/enums.ts` 各一份 A/B/C/D）。
- 审批模板：**已有后台可配**（表 `review_templates` + 管理后台页，已支持逐节点指定审批人）→ 本轮**复用**，仅把 key 改为跟随类型。
- 生命周期模板：有后台页，但类型写死为 A/B/C/D（`web/src/pages/admin/AdminTemplatesPage.tsx` 的 `MenuItem value="A".."D"`）→ 本轮改为跟随类型列表。
- 建项时的"自动推荐 / 特征勾选 / 覆盖理由"（`classify.service.js`）→ 本轮**移除**。

## 2. 用户故事

| # | 角色 | 故事 |
|---|---|---|
| US-1 | PMO / 管理员 | 作为管理员，我希望**新增一个项目类型**（填名称、例子），以便业务出现新品类时不用改代码就能建项。 |
| US-2 | PMO / 管理员 | 作为管理员，我希望为**每个类型分别配置生命周期模板与审批流**，以便不同类型的项目走各自该走的里程碑与审批链。 |
| US-3 | PMO / 管理员 | 作为管理员，我希望**新增类型时可以"克隆自某类型"**，以便快速复刻一套现成模板、只做少量改动。 |
| US-4 | PMO / 管理员 | 作为管理员，我希望类型**只能停用、不能物理删除**，以便历史项目引用的类型不被破坏。 |
| US-5 | 项目经理 | 作为项目经理，我希望建项时从**启用中的类型直接单选**（含例子提示），以便快速、无歧义地选对类型。 |
| US-6 | 项目经理 | 作为项目经理，我希望**已停用类型的历史项目仍能正常显示原类型并继续流转**，以便不受后台配置变动影响。 |

## 3. 需求池

优先级口径：**P0 = 必须有（本轮交付）**，**P1 = 应该有（本轮尽量）**，**P2 = 可后置**。

| ID | 优先级 | 需求 |
|---|---|---|
| R1 | P0 | **类型列表**：管理后台新增「项目类型」页，展示所有类型（名称 / 例子 / 启用状态 / 排序）。 |
| R2 | P0 | **新增类型**：填名称、例子；**标识由系统自动生成且不可改**；默认**空白起步**（无模板）。 |
| R3 | P0 | **编辑类型**：可改名称、例子、排序、启用开关。 |
| R4 | P0 | **停用类型**：停用后不再出现在建项下拉；**不做物理删除**。 |
| R5 | P0 | **每类型配生命周期模板**：在该类型编辑页内配置里程碑 + 质量门（类型 ↔ 模板 **1:1**）。 |
| R6 | P0 | **每类型配审批流**：在该类型编辑页内配置审批链节点 + 每节点审批人；审批 key 跟随类型（立项 `project:<类型>`，变更 `ccb:<类型>`）。 |
| R7 | P0 | **建项直接单选类型**：建项页从"启用中的类型列表"单选，展示名称 + 例子；**移除**自动推荐、特征勾选、覆盖理由。 |
| R8 | P0 | **停用类型的表现**：建项不可选；历史项目仍显示原类型名、仍按已绑定的模板与审批流继续流转。 |
| R9 | P1 | **克隆新建**：新增类型时可选"克隆自某类型"，一键带出该类型的生命周期模板 + 审批流作为新类型的初值。 |
| R10 | P1 | **类型被引用时禁止删除**：若某类型已被项目引用，删除入口不可用并给出提示（本轮的"删除"= 停用兜底）。 |
| R11 | P1 | **配置权限**：类型的新增 / 编辑 / 停用仅对 PMO / 管理员开放，普通项目经理只读、只能在建项时单选。 |
| R12 | P2 | 类型变更审计（谁在何时改了什么）——可后置。 |
| R13 | P2 | 类型停用前的影响面提示（如"当前有 N 个在用项目"）——可后置。 |

## 4. 验收口径（可勾选行为清单）

- [ ] 管理后台存在「项目类型」页，能列出全部类型及其名称 / 例子 / 启用 / 排序。
- [ ] 能新增一个类型；标识由系统生成且不可编辑；新增后默认无模板（空白）。
- [ ] 能编辑类型的名称、例子、排序、启用开关，保存后列表与建项页同步生效。
- [ ] 能停用一个类型；停用后该类型**不再出现在建项下拉**。
- [ ] 每个类型的编辑页内可配置**里程碑 + 质量门模板**，且与类型一一绑定。
- [ ] 每个类型的编辑页内可配置**审批链节点与每节点审批人**，审批 key 跟随类型。
- [ ] 建项页类型为**单选**，选项来自"启用中的类型列表"，并显示例子辅助识别。
- [ ] 建项页**不存在**自动推荐、特征勾选、覆盖理由等控件。
- [ ] 历史项目引用的类型即便被停用，**项目详情仍正常显示原类型名**。
- [ ] 停用类型的存量项目**仍按其已绑定模板与审批流继续流转**，不中断。
- [ ] 新增类型时可选"克隆自某类型"，克隆后新类型自带一套同样的模板与审批流（作为初值，可再改）。
- [ ] 已被项目引用的类型，**无物理删除入口**（或点击后拒绝并提示）。
- [ ] 非管理员角色**无法**新增 / 编辑 / 停用类型。

## 5. 边界与异常

1. **停用类型的项目如何显示**：历史项目保留其原类型（名称 + 例子可正常展示，含"已停用"可选标记）；不因类型停用而清空或改写项目类型。
2. **停用类型的项目是否继续走审批**：**继续**。已建项目按其**创建时绑定**的模板 / 审批流走完，后台停用类型不影响在途流程。
3. **克隆的规则（克隆哪些内容）**：仅克隆 **①生命周期模板（里程碑 + 质量门）** 与 **②审批流（节点 + 审批人）** 作为新类型的初值；**不克隆**标识（系统重新生成）、不迁移任何项目引用。克隆后可独立修改，互不影响。
4. **模板与类型的绑定与解析**：类型 ↔ 模板为 **1:1**；建项时按所选类型解析出对应的生命周期模板与审批流（立项 `project:<标识>`、变更 `ccb:<标识>`）。若某类型**尚未配置**模板 / 审批流 → 建项应给出明确提示（需先配置或使用默认），**不得**静默取用其他类型。
5. **谁有权配置（权限）**：类型 CRUD、模板与审批流配置 = PMO / 管理员；普通项目经理 = 只读 + 建项单选。权限沿用现有后台权限矩阵。
6. **类型被引用时禁止删除**：本轮**不提供物理删除**；若在 UI 暴露删除入口，被引用时必须拒绝并提示（引用中的类型请改用"停用"）。
7. **排序**：类型列表按"排序"字段升序；新增类型默认排到末尾。

---

## 6. 明确非目标（本轮不做）

- ❌ 类型与模板的**多对多复用**（本轮固定 1:1）。
- ❌ 类型的**物理删除**（一律停用）。
- ❌ **存量数据迁移**（业务方明确本轮不谈）。

## 7. 待业务方拍板的开放问题

| # | 问题 | 建议默认值 |
|---|---|---|
| OQ-1 | 类型**未配模板 / 审批流**时建项的行为：**阻止建项** 还是 **允许并走系统默认流程**？ | 建议**阻止并提示**，避免流程缺口 |
| OQ-2 | 停用类型在项目详情是否展示**"已停用"标记**？ | 建议**展示**，便于辨识 |

| OQ-5 | 标识的**生成规则与格式**（如 `T1/T2/...` 或 `pt_<n>`）——本轮由实现定，仅需"稳定且创建后不变"。 | 由架构师定 |

> 备注：以上开放问题均有建议默认值，**不阻塞**架构与开发启动。
