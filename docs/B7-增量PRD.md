# 工时设置（B7）· 增量 PRD

> **文档性质**：增量变更定义（只描述相对 B5/B6 交付后的本次改动），非全盘重设计。
> **基线**：WBS 树（`wbs_nodes`，v2 迁移建表；`migrations.js` 当前 v3）已有 任务/子任务 层级、`nodeType`（task/milestone）、`parentId`、`progress`（0~100）、`milestoneId`；父节点进度已有自动汇总（B3「WBS进度汇总与自动流转」，`server/services/wbs.service.js#syncWbsProgressStatus` 自底向上回写）。
> **落地方式**：本 PRD 作为 PM→架构→工程师→QA 的标准输入。**纯文档产出，不写代码、不碰数据库。**
> **范围**：WBS 工时字段（`wbs_nodes.effort_hours`，migrationV4）+ `wbs.service.js` 校验与汇总 + `WbsPage.tsx` 编辑弹窗/树行展示 + 前端类型/契约（`types/wbs.ts` / `contract.ts`）；不涉及日志、看板、审批等模块。
> **默认主题**：浅色（`themeContext.tsx#DEFAULT_THEME_MODE='light'`）；品牌青交互色 `#2E7D87`、装饰色 `#6DA8AE`（见 `theme/tokens.ts`）。
> **已确认方案**：方案 A「强制汇总」——叶子任务可设工时，父任务工时**自动 = Σ子任务工时、只读展示**，服务端强制校验防绕过。

---

## 0. 产品目标（一句）

让 WBS 工时「叶子可填、父级自动汇总、服务端强制一致」：任何人查看任意节点的工时都能得到与树结构一致的准确数值，从机制上根治「父节点工时与子任务对不上」的账实不符问题（延续「有子节点任务禁止关联日志」的思路）。

## 1. 用户故事

| # | 用户故事 |
|---|---------|
| US1 | 作为项目成员（叶子任务负责人），我想在 WBS 任务编辑弹窗里为**叶子任务**设置/修改「工时(h)」（如 0.5、40），以便如实登记我的工作量；填错小数或超上限时能立即得到提示。 |
| US2 | 作为项目经理，我希望**父任务/子任务**的工时**自动等于其全部子任务工时之和**且不可手填，并有「由 N 个子任务汇总」的说明，以便一眼看清单个交付块的总投入，杜绝手填导致的对不上账。 |
| US3 | 作为项目经理，我在 WBS 上**新增/删除/移动子任务**或修改任一子任务工时后，希望父节点工时**实时自动重算**，无需任何手工同步操作。 |
| US4 | 作为后端使用方/集成方，我希望「有子节点禁止手填工时」是**服务端强约束**（直接抛错），而不是仅前端禁用，以便即使绕过前端也无法写入脏数据。 |

## 3. 关键交互说明

### 3.1 编辑弹窗：叶子输入 / 父节点只读汇总（B7-R2/R3）

**位置**：`WbsPage.tsx` 任务新建/编辑 `FormDialog`（现有字段：名称/类型/里程碑/截止日期/负责人/工时估算（人日）/状态；新增「工时(h)」字段，与现有 `estimateDays` 并存，见 Q5）。

**交互规则**：

1. **叶子节点（无子节点）**：
   - 显示**可编辑**数字输入框，label `工时(h)`，`type=number`，`min=0`，`step=0.5`，上限默认 1000（可配）；
   - 允许小数（如 0.5）；失焦/提交时校验：`0 ≤ 值 ≤ 上限`，非法值前端提示 + 后端 `E_VALIDATION`；
   - 空值按 `0` 处理（显示 0）。
2. **父节点（有子节点）**：
   - 显示**只读**值 = Σ全部直接子节点 `effort_hours`（递归展示口径见 3.3）；
   - 输入框 `disabled` + 灰显，旁边文案 `由 N 个子任务汇总`（N=直接子节点数），tooltip 完整说明 `由 N 个子任务汇总：子任务工时之和，不可手填`；
   - 提交时前端不发送该字段；即使构造请求发送，后端也拒绝（见 3.2）。
3. **树行展示（默认关闭，见 Q2）**：若开启，树行节点名右侧显示 `工时(h)` 小字/ Chip（叶子=实际值，父=汇总值，父级加「Σ」前缀）。

### 3.2 服务端强制校验与实时重算（B7-R4/R5）

**校验（`createWbsNode` / `updateWbsNode`）**：

1. payload 携带 `effortHours` 时：
   - 若节点**已有子节点**（创建场景即 `parentId` 指向的父级；更新场景即该节点 `children.length > 0`）→ 抛业务错误（如 `E_WBS_EFFORT_PARENT`，message 建议：`有子节点的节点工时由子任务自动汇总，不可手填`），HTTP 4xx；
   - 否则校验数值：`Number.isFinite`、`≥ 0`、`≤ 上限`（默认 1000），不合法抛 `E_VALIDATION`。
2. 叶子节点 `effortHours` 缺省：按 `0` 落库（或 NULL，架构师定，展示按 0）。

**实时重算（所有写操作统一走同一汇总函数）**：

- 在现有 `syncWbsProgressStatus` 所在的写操作事务内（create/update/delete/move 均触发）增加工时汇总：
  - 自底向上：`effort_hours = Σ children.effort_hours`，父节点该列**不存**（保持 NULL），仅参与返回展示；
  - 子任务工时变更（update 叶子）→ 立即重算其父链所有祖先；
  - 删除/移动子任务 → 重算原父与现父的祖先链；
- 前端 `listWbs` 返回时，对每个节点附带 `effortHours`（叶子=存储值，父=服务端递归求和结果）与 `effortChildCount`（直接子节点数，供「由 N 个子任务汇总」文案），避免前端各自求和口径不一致。

### 3.3 数据模型（B7-R1）

- `migrationV4`：`ALTER TABLE wbs_nodes ADD COLUMN effort_hours REAL`（可空，默认 NULL）。
- **父节点约定**：父节点该列保持 NULL / 不存值（避免与 Σ 冲突、出现「存了值但没算」的脏态）；展示时由服务端递归求和。
- **缓存列权衡（架构师定）**：量级小时推荐「不落缓存列、读取时递归求和」（简单、天然一致）；若树深/节点量大再引入冗余缓存列 + 写时重算，PRD 不做强制。
- 现有 `estimate_days`（人日）、`actual_days` 字段**不受影响**；两者与 `effort_hours` 的关系见 Q5。

### 3.4（P1，待确认）父节点进度加权（B7-R6）

- 若确认本期做：`syncWbsProgressStatus` 中父节点 `progress = Σ(child.progress × child.effort_hours) / Σ(child.effort_hours)`；
- 全部子节点 `effort_hours = 0` 时回退现逻辑（简单平均，`Σprogress / N`），避免除零；
- 前端 `utils/wbs.ts#weightedProgress` 同步改为以 `effortHours` 为权重（现用 `estimateDays`），保证列表数字与后端一致（沿用「列表与钻取基于同一份数据」约定）。
- 默认建议：**本期不做**（P1 后续），避免与 B3 已交付的进度汇总回归面叠加。

## 6. 一句话总结

> 工时设置 B7（方案 A 强制汇总）：WBS 节点新增 `effort_hours` 列（migrationV4），叶子任务可在编辑弹窗设置工时（≥0、允许小数、上限默认 1000），父任务工时由服务端**只读强制汇总 = Σ子任务工时**并展示「由 N 个子任务汇总」文案，任何新增/删除/移动/修改子任务都在同一事务内实时重算父链，服务端对有子节点的节点拒绝手填工时（防绕过），从机制上根治工时账实不符；父节点进度按工时加权与列表/看板展示工时列为 P1 待确认项（默认本期不做）。
