# 后台可配置的「项目类型」· 设计稿

> 设计稿（**已定稿 2026-09-11**），**未动代码**。仅设计口径；数据迁移、实现细节不在本文范围。

---

## 一、目标

把"项目类型"从**写死的 A/B/C/D** 变成**后台可维护的实体**：

- 能在后台**新增 / 编辑 / 停用**类型；
- 每个类型可配置 **①里程碑 / 质量门模板** 和 **②审批流**；
- 以后加新类型（如"预研类"）只靠后台配置，**不用改代码**。

---

## 二、现状 → 目标

| 能力 | 现状 | 目标 |
|---|---|---|
| 类型本身 | 写死在代码（前后端各一份常量） | 后台可增 / 改 / 停用 |
| 里程碑 / 质量门模板 | 有后台页，但类型写死成 A/B/C/D | 跟随类型列表，每类型一套 |
| 审批流 | 已有后台可配（复用） | key 跟随类型，仍后台配置 |

---

## 三、类型实体（字段草案）

| 字段 | 说明 |
|---|---|
| 标识 | 稳定、系统生成、创建后不变（用于挂接模板） |
| 名称 | 显示名（如"基建类"），可改 |
| 例子 / 说明 | 可选（如"卫星 / 地面站 / 激光"），显示在建项处帮你识别 |
| 启用 | 停用后建项不可选；历史项目仍保留原类型 |
| 排序 | 列表顺序 |

> 初始 4 条：基建类（卫星 / 地面站 / 激光）、载荷产品类（计算 / 网络 / 存储）、软件产品类（平台 / 应用）、通用类（行政 / 人力 / 其他）。

---

## 四、后台交互（管理后台 →「项目类型」）

- **列表**：所有类型（名称、例子、启用、排序）。
- **新增**：填名称 / 例子；可选"**克隆自某类型**"，一键带出一套模板起步。
- **编辑单个类型** → 三块：
  1. 基本信息（名称 / 例子 / 排序 / 启用）
  2. **生命周期模板**：该类型的里程碑 + 质量门
  3. **审批流**：审批链节点 + 每节点审批人
- **停用**：不再出现在建项下拉；已有项目不受影响。

---

## 五、两个模板怎么挂

- **每个类型 = 一套生命周期模板 + 一条审批流**，成对绑定，在该类型的编辑页里一起配（先做 **1:1**，简单够用）。
- 审批流按类型挂：立项走 `project:<类型>`，变更走 `ccb:<类型>` —— **都是后台配置，不改代码**。

---

## 六、建项处的变化

- 类型 = 从"**启用中的类型列表**"里**直接单选**（无自动推荐）。
- 移除：现在的特征勾选框、覆盖理由、分类推荐逻辑。

---

## 七、本轮不做（非目标）

- 类型与模板的"多对多复用"（先 1:1）。
- 类型的物理删除（一律**停用**）。
- 存量数据迁移（另议，不在本文）。

---

## 八、决策记录（已定稿 2026-09-11）

| # | 定项 | 结论 | 理由 |
|---|---|---|---|
| 1 | 类型字段 | **5 个**：标识 / 名称 / 例子 / 启用 / 排序 | 增字段 = 增理解成本；真有用例再加 |
| 2 | 类型 ↔ 模板 | **1:1** | 一个类型一套流程，最直白；无"多类型共用一套模板"场景 |
| 3 | 新增类型 | **默认空白 + 可选"克隆自某类型"** | 空白最直观；想省事就克隆 |
| 4 | 删除 / 停用 | **不删只停** | 历史项目引用了类型，物理删除会破坏历史 |
| 5 | 类型的"标识" | **系统自动生成**，不用手填 | 免去起英文标识的心智负担 |

> 以上 5 条已于 2026-09-11 与用户确认，**设计定稿**。
