# 工时登记时机与单位修正（B8）· 增量 PRD

> **文档性质**：增量变更定义（对 B7 已交付「工时设置」的**语义修正**，非新增功能）。
> **基线**：B7 已交付（`wbs_nodes.effort_hours(h)` 列 + WBS 编辑弹窗「工时(h)」输入 + 父节点 Σ 只读 + `E_WBS_EFFORT_PARENT` 防绕过 + `decorateEffort` 读时汇总）；B5 已交付工作日志（`ReportFormModal` + `work_reports` / `work_report_tasks`，submit 时回写进度）。
> **用户修正意见（已确认，两点拍板）**：① 创建任务时**不应**出现「工时(h)」——创建任务只保留「工时估算（人日）」（该命名无歧义，保留不改）；② 实际工时在**工作日志**时填写；③ **单位统一用人日**（不用小时）。
> **已确认方案**：登记位置 = 工作日志（ReportFormModal）「关联任务」**每行**「本周实际工时（人日）」；提交日志时累加到节点「累计实际工时（人日）」，父节点自动 Σ 子任务（延续 B7 汇总语义）。
> **落地方式**：本 PRD 作为 PM→架构→工程师→QA 的标准输入。**纯文档产出，不写代码、不碰数据库。**
> **默认主题**：浅色；品牌青交互色 `#2E7D87`、装饰色 `#6DA8AE`（同 B7）。

---

## 0. 产品目标（一句）

把「工时」从创建任务时的预填字段改为**工作日志提交时的实际登记**：任务节点不再手填工时，改由日志每行登记「本周实际工时（人日）」，提交时累加为「累计实际工时（人日）」，父节点自动 Σ 只读展示，实现「工时估算」与「实际投入」彻底分账、账实一致。

## 3. 关键交互说明

### 3.1 WbsPage 弹窗字段变化（B8-R1，破坏点）

**位置**：`WbsPage.tsx` 任务新建/编辑 `FormDialog`。

**变更**：
1. **移除** B7 新增的「工时(h)」输入框（叶子可填 / 父节点只读汇总那一整块，含 helperText 与 Tooltip）——创建/编辑任务弹窗**不再出现**任何「工时(h)」字段；
2. 保留「工时估算（人日）」（`estimateDays`）不动，命名与语义不变；
3. 节点展示「累计实际工时（人日）」**只读**：
   - 叶子 = 自身累计值（历次已提交日志累加）；
   - 父节点 = Σ 直接子节点累计值，附「由 N 个子任务汇总」文案（沿用 B7 `effortChildCount` 口径）；
   - 展示位置：编辑弹窗内**只读文本行**（P0）；树行/看板加列属 R7（P1，本期不做）；
4. WBS 创建/编辑 payload **不再携带 `effortHours`**；服务端 WBS API 对携带 `effortHours` 的请求直接拒绝（防绕过，见 3.5）。

### 3.2 日志行内输入「本周实际工时（人日）」（B8-R2）

**位置**：`ReportFormModal.tsx#renderTaskTree` 每行（现有「完成进度(%)」旁新增一列输入）。

**交互规则**：
1. **叶子行**：新增 `TextField`，label「本周实际工时（人日）」，`type=number`、`min=0`、`step=0.5`、上限默认 100（可配）；
   - **仅勾选可填**：未勾选 → `disabled` 灰显（值保留但不提交）；勾选 → 可编辑；
   - 允许 0 或小数（如 0.5）；校验 `0 ≤ v ≤ 100`，非法值前端提示 + 后端 `E_VALIDATION`；
   - 新建态默认 0；编辑态回显 `work_report_tasks.week_actual_days`。
2. **父节点行**：恒禁用（父节点本不可勾选，沿用 B5 行级禁用 + Tooltip），不登记本周工时；
3. **编辑态（冲正入口）**：B5「编辑已提交日志任务区只读」口径**仅放开本周实际工时输入**——勾选与「完成进度(%)」仍只读，**「本周实际工时（人日）」输入放开可编辑**并回显原值，提交后走 R4 冲正；
4. 提交（submit）时该字段随 `tasks[].actualDays` 进入 payload；**存草稿时不提交、不累加**。

### 3.3 数据模型（B8-R3）

- **migrationV5**：
  - `wbs_nodes`：`effort_hours` 列**语义改造为「累计实际工时（人日）」**。列名：⚠️ **不能直接复用 `actual_days`**（该列已被 B3 占用，语义 = `estimate_days × progress/100` 的进度折算值，且在 `syncWbsProgressStatus` 中回写）；推荐方案 A **保留 `effort_hours` 列名不改**（最小改动、QA 脚本改动小），方案 B RENAME 为 `cum_actual_days`（语义更清晰，SQLite `ALTER TABLE ... RENAME COLUMN` 由架构师评估）；
  - `work_report_tasks`：新增 `week_actual_days REAL NOT NULL DEFAULT 0`（本周实际工时·人日）；
- **存量处置**：当前 `pm.db` 已清空、无存量业务数据 → **无需单位换算**；若未来其他环境存在存量 `effort_hours`（小时）值，按 Q4 策略处理（默认按 0 起步不回填，或 8h=1 人日换算，由产品确认）；
- **契约**：`ReportPayload.tasks[]` 扩展 `actualDays?: number`（本周，人日；仅勾选行携带）；WBS 节点出参 `effortHours` 字段名随列名决策（方案 A 保留 `effortHours` 但语义变人日；方案 B 改名 `cumActualDays`），`effortChildCount` 保留；
- **累加规则**：日志 **submit** 事务内，对每个勾选且 `actualDays > 0` 的任务：`UPDATE wbs_nodes SET effort_hours = effort_hours + ? WHERE id = ?`；随后父链 Σ 由 `decorateEffort` 读时汇总（沿用 B7，不落冗余缓存值）。**草稿（save）不累加。**

### 3.4 冲正（B8-R4）

- **编辑已提交日志**（`updateReport`，同事务）：
  - 对每行对比「旧 `week_actual_days`（原日志行） vs 新值」：`delta = new - old`；
  - `UPDATE wbs_nodes SET effort_hours = effort_hours + delta`（delta 可正可负）；父链 Σ 随之重算；
  - 任一失败整体回滚，不产生半更新；
- **删除日志**：对日志每行 `UPDATE wbs_nodes SET effort_hours = effort_hours - week_actual_days`；⚠️ 当前代码库**无日志删除接口/入口**（`contract.ts` 仅有 save/submit/update），需架构师确认本期是否新增删除能力，或「删除扣减」仅作规则预留（见 Q2）；
- **草稿**：不累加、不冲正（仅 submit 与已提交日志的编辑生效）。

### 3.5 服务端约束与防绕过（B8-R5）

1. `week_actual_days` 校验（日志提交/编辑）：`Number.isFinite`、`0 ≤ v ≤ 100`、最多 2 位小数，非法抛 `E_VALIDATION`（message 含「人日」口径）；未勾选行携带 `actualDays` 直接拒绝（或忽略，架构师定，推荐拒绝）；
2. **WBS API 不再接受 `effortHours` 写**：创建/编辑任务若携带 `effortHours` → 抛业务错误（沿用 `E_WBS_EFFORT_PARENT` 或新增 `E_WBS_EFFORT_WRITE_DISABLED`，架构师定），HTTP 4xx——工时唯一写入通道是日志提交；
3. 父节点 Σ 只读：展示口径沿用 B7（叶子 = 存储累计值，父 = Σ 直接子节点 + `effortChildCount`），服务端读时强制求和，不信任前端计算；
4. 累计值约束：`effort_hours ≥ 0`（扣减不得导致负数，抛 `E_VALIDATION`）；防溢出上限建议 `10000`（人日，可配常量，架构师确认）。
